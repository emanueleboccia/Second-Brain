# Review settimanale

Un file per settimana: `AAAA-Wnn.md`, per esempio `2026-W36.md`. Si copia `_template.md`.

Si fa **la domenica**, dentro la sessione, col comando «review settimanale» della skill
[journal](../../code/skills/journal/SKILL.md). Non è un compito da fare da soli davanti a un
foglio bianco: Claude porta i fatti della settimana — le note di sessione, le task chiuse, lo
stato delle proposte, le righe nuove del registro — ed Emanuele risponde partendo da quelli.

Quattro blocchi: le vittorie, il giro delle aree, gli obiettivi, le tre priorità della settimana
dopo. Le tre priorità sono quelle che il briefing del lunedì rilegge.

**Non è un riassunto della settimana** — quello sta già nel journal. È il punto in cui si guarda
da sopra invece che da dentro.

## A cosa serve tenerle tutte

Una review da sola vale poco. La serie vale molto: è l'unico posto da cui si può rispondere a
«com'è andato questo periodo» senza andare a memoria. Per questo il formato non cambia — se ogni
settimana ha una forma diversa, la serie non si legge.

`workspace/` sta fuori dal gate di qualità e fuori da `llms.txt`: queste note si leggono aprendo
la cartella, non cercandole nell'indice.
